# Active contract detail

The Contracts tabs on `host.php` and `renter.php` now load current contract detail from `Contracts_Active` in `include/config.php`'s `database.raw_database`. The host no longer downloads its entire contract history from the explorer during page rendering. The host Contracts tab now shows summary, renter distribution, and expiration exposure only. Its Browse contracts link opens `/host_contracts?public_key=...`, which has Active and Completed tabs with filters, pagination, refresh controls, and a back-to-host link. Completion history is fetched only when the dedicated Completed tab is opened. The renter widget is mounted only after the existing wallet/key resolver supplies the canonical wallet address.

Both profiles show active-contract counts, contracts with stored data, empty contracts, contracted bytes, the top eight counterparties plus Others, and a distribution chart. Both profiles now keep summaries only. Renter lists live on `/renter_contracts?address=<wallet>`; host lists live on `/host_contracts?public_key=<key>`. Both pages use the same template and browser logic with Active/Completed tabs. Renter rows link to hosts; host rows link to renter wallets. Renter counterparts are hosts; host counterparts are renter wallets, rather than public keys. Links navigate to the corresponding profiles and contract/renewal predecessor details. Unknown wallet identities are distinct from Others and do not inflate wallet counts. The list supports exact full-contract-ID search, fixed 25-row pages, and ending/largest/newest ordering. Search filters the list, not the profile summaries. Ending order includes null end heights first; newest uses confirmation height.

End windows are mutually exclusive: at/past the reference height, next 144 blocks, 145–1008, 1009–4320, later, and unknown. The UI estimates days at 144 blocks/day. Do not infer failed/resolved state from an old end height: membership in the producer's active table remains authoritative. `BlockTime` supplies the latest indexed reference height and its stored timestamp; it is not proof that contract updates have reached that height. There is no certified publication marker. API metadata marks completeness as unverified/partial. Missing BlockTime disables window estimates, not the rest of the view.

Host Economics shows total stored `revenue_locked`; Contracts retains exposure by end window and per-contract locked revenue. These are committed, not earned, amounts, using Hastings and the site's currency formatter. Economics loads independently of Contracts; identical first-page active requests share an in-flight/recent response for 60 seconds. Existing daily metrics, wallet summaries, historical charts, and `HostRevenueForecast` remain their existing sources. No refundable allowance, collateral, or spending is inferred from raw output balances.

The host's Charts tab is now labelled History, with `#history` used for new navigation and `#charts` retained as a bookmark alias. Historical Contract Activity moved from Economics into History beside storage/pricing history. Its 12M/24M/All controls are independent of Economics ranges. Overview retains its brief scores and performance summary, with detailed measurements in Benchmarks. Contracts explains that contracted bytes are summed active contract filesizes and can differ from Overview's used-storage source.

## APIs

- `GET /api/v2/contracts/active.php?address=<wallet>` or `?host_public_key=<key>`; exactly one identity is required. Optional `page=1..10000`, `sort=ending|size|newest`, and `search=<64-character contract ID>`.
- `GET /api/v2/contracts/completed.php?host_public_key=<key>` returns up to 25 resolved contracts plus `pagination.has_more` and `pagination.next_after`. Optional `sort=newest|oldest`, `search=<contract ID>`, and `after=<next_after>` support investigation beyond the latest results. Keep sort/search unchanged when continuing a cursor. A primary-key probe excludes older resolved revisions of each contract/version. Two host-key equality queries preserve indexed chronological access for bare/prefixed encodings; each fetches at most 27 candidates to include the possible two-version tie at a page boundary. Ordering uses resolution height, contract ID, block height, revision number, and a version tie-breaker. Version ties are merged in PHP to avoid a SQL sort outside the installed index. Cursors preserve large revision numbers as decimal strings. Host history uses the existing host index. Renter completed history requires the additional wallet-first index in `docs/sql/renter-contract-history-index.sql`; it has not been applied to the application database.

Both use the V2 `{data, meta, errors}` envelope. All source numeric values and SQL aggregates remain decimal strings; null remains unknown. An amount is only summed when every contributing value is known. All aggregates, including Others, use SQL exact arithmetic, avoiding the optional PHP BCMath fallback. Only chart coordinates use floating point; display shares use BigInt. UI currency changes reformat loaded values without refetching contracts.

Successful API responses, including empty results, cache for 60 seconds in Redis. Missing Redis is tolerated. Browsers receive `Cache-Control: no-store`. Validation errors return 400, non-GET requests 405, and infrastructure failures 503 without caching errors. SQL values are parameterized and ordering is allowlisted. Connection/read timeouts are 5/10 seconds. Active summary, grouping, windows, reference, and list queries run in one read-only consistent-snapshot transaction; this cannot certify the producer's multi-transaction publication.

## Index deployment

Apply [active-contract-indexes.sql](sql/active-contract-indexes.sql) through the database deployment process. The file uses the current schema name, `siagraph_raw`; adjust it if configuration changes. It was **not applied to the application database**.

| Table | New index | Purpose |
| --- | --- | --- |
| Contracts_Active | `(renter_wallet_address, windowend, contract_id)` | Scoped renter summaries and ordered deadline pagination. |
| Contracts_Active | `(host_public_key, windowend, contract_id)` | Host lookups across contract versions, including both key encodings. |
| Contracts | `(host_public_key, resolution_height DESC, contract_id DESC, block_height DESC, revisionnumber DESC)` | Retrieve newest host completions in order; existing primary key supports revision deduplication. |

Keep existing producer indexes. The current host index begins with `v2`, so it does not replace the proposed host-first index for queries covering both versions. Largest/newest sorts may sort the matching profile's current rows; no extra sort-specific indexes are proposed without workload evidence. Historical queries can remain expensive until their index is installed, but they no longer block page rendering or current-state results.

## Verification

`php tests/contracts/service.php` checks identity validation. `php tests/contracts/service.php --database --local` creates and deletes a uniquely named fixture schema in a disposable MySQL 8.4 instance on `127.0.0.1:13376`, root password `contract-fixture-only`. It tests exact large sums, nulls, empty contracts, key normalization, pagination, search scoping, deadline boundaries, Others/unknown identities, resolution deduplication, index plans, and API validation/failure envelopes. Without `--local`, `--database` uses configured credentials and requires permission to create the disposable schema; no application tables are changed.

`node tests/contracts/browser.cjs` runs headless Chrome using local synthetic responses and real widget markup from both pages. It checks lazy tab loading, links, exact values, currency changes, pagination, search, empty/error/retry behavior, absence of completion-history requests on the host summary, and mobile overflow. Chart.js is stubbed: these are DOM/data checks rather than rendered-chart pixel tests.

The MySQL fixture suite and four Chrome scenarios passed, as did existing renter browser/currency/format and host chart/forecast checks. Read-only smoke queries against the configured database returned valid active views for an actual renter and host. Production history-query latency has not been benchmarked with the proposed index installed.

`node tests/contracts/page-browser.cjs` checks the real dedicated page markup with synthetic responses: Active/Completed deep links, lazy loading, cursor/numbered pagination, sorting, search, errors/retry, back navigation, and mobile overflow. The database suite also verifies more than 25 completed contracts, both key encodings, tied heights/versions, 20-digit revisions, and both sort directions. Invalid host identifiers render a 400 page without starting API requests.

## Renter navigation

The renter profile labels Charts as History, preserving `#charts` bookmarks and accepting `#history`. Contract lifecycle charts moved into History alongside storage/host history; financial charts remain in Economics. Contracts retains current metrics, host distribution, expiration exposure, and a Browse contracts link built from the resolved canonical wallet (including public-key profile entry). `/renters` separates Wallets and network History into tabs while keeping the published network summary visible. Directory searches retain the current hash. The dedicated renter browser accepts a 76-character `address`; invalid input returns 400 without an API request. Completed APIs now accept either `address` or `host_public_key`, exclusively.

## Profile refresh and explanations

Host and renter profile summaries have no refresh/retry controls. Each summary and the host anticipated-revenue loader makes one initial load attempt per page visit; changing tabs does not retry failures. Renter history reuses results for an already requested date range throughout the page visit; new date criteria can load new results. Supporting explanations have moved from paragraphs below profile/chart headings into native hover tooltips on headings and metric labels. Loading, error, and source-freshness statuses remain visible. Dedicated contract-browser search, sorting, and pagination remain available.
